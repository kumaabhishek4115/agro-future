# Farmer Portal Backlog

This backlog translates the [technical requirements document](./carbon-credit-technical-requirements.md) into implementation-ready backlog items for the farmer-facing MVP surface.

## Prioritization Principles
- Focus first on the supplier workflows called out in TRD sections 5.1-5.3 and the MVP acceptance criteria.
- Sequence work so farmers can complete the end-to-end journey: register -> create profile -> submit project -> upload documents -> respond to review outcomes -> review offers -> track payouts.
- Leave buyer and internal-only enhancements for later milestones unless they block the farmer experience.

## Epic 1: Farmer account onboarding

### P0 — Supplier account registration
- **TRD reference:** 4, 5.1, 7, 8
- **Backlog item:** Build supplier registration, login, and email verification flows with role-based access control.
- **Acceptance notes:**
  - Farmer can create an account and verify email before accessing protected portal pages.
  - Protected farmer routes are deny-by-default for unauthenticated users.
  - Supplier role is enforced separately from buyer, operator, and admin roles.

### P0 — Supplier profile setup
- **TRD reference:** 5.1, 6
- **Backlog item:** Create profile capture and edit flows for geography, land size, crop/livestock type, ownership or lease status, and payout details.
- **Acceptance notes:**
  - Required profile fields are validated before profile completion is marked complete.
  - Saved profile data maps cleanly to `supplier_profiles`.
  - Farmers can revisit and update profile details without losing previously entered data.

## Epic 2: Project intake and document submission

### P0 — Project draft creation
- **TRD reference:** 5.1, 6, 7
- **Backlog item:** Implement a farmer project form with draft and submitted states for methodology, geography, baseline, expected volume, and project metadata.
- **Acceptance notes:**
  - Farmers can save incomplete work as a draft and resume later.
  - Submission is blocked until required fields pass validation.
  - Project state transitions are visible in the farmer portal.

### P0 — Project document upload
- **TRD reference:** 3.1, 5.1, 6
- **Backlog item:** Add document upload support for registry evidence, MRV records, and land ownership proofs.
- **Acceptance notes:**
  - Farmers can attach multiple documents to a project.
  - Stored files keep document type, storage URI, and checksum metadata.
  - Invalid or missing required document types are surfaced before final submission.

### P1 — Submission confirmation and intake timeline
- **TRD reference:** 5.2, 8
- **Backlog item:** Show farmers a submission receipt and timeline of review status changes.
- **Acceptance notes:**
  - Timeline includes status, actor, timestamp, and reason when applicable.
  - Farmers can distinguish `draft`, `submitted`, `in_review`, `needs_info`, `approved`, and `rejected`.

## Epic 3: Farmer response to review workflow

### P0 — Needs-info resolution flow
- **TRD reference:** 5.2
- **Backlog item:** Let farmers view review feedback, update their project, and resubmit when operations requests more information.
- **Acceptance notes:**
  - Reject and needs-info decisions show required reason text.
  - Farmers can edit the requested fields and upload replacement documents.
  - Resubmission preserves the project history for audit purposes.

### P1 — Review status dashboard
- **TRD reference:** 5.2, 5.6
- **Backlog item:** Add a farmer dashboard card or page for active projects and their current review status.
- **Acceptance notes:**
  - Farmers can quickly see which projects require action.
  - Status history aligns with audit log events recorded by the platform.

## Epic 4: Offer review and contract acceptance

### P0 — Offer inbox and detail view
- **TRD reference:** 5.3, 6
- **Backlog item:** Surface versioned offers in the farmer portal with pricing model, fees, payout schedule, delivery expectations, and liability clauses.
- **Acceptance notes:**
  - Farmers can clearly identify the latest active offer version.
  - Offer details are read-only once generated by operations.
  - Fee and payout terms are presented before farmer action is requested.

### P0 — Offer accept or reject workflow
- **TRD reference:** 5.3, 10
- **Backlog item:** Implement accept and reject actions for farmers and generate a contract record when an offer is accepted.
- **Acceptance notes:**
  - Acceptance creates an immutable contract snapshot linked to the accepted offer.
  - Reject action captures status change cleanly without altering prior offer versions.
  - The submission -> approval -> offer acceptance path supports the MVP end-to-end scenario.

### P2 — Counter-offer capability
- **TRD reference:** 5.3
- **Backlog item:** Evaluate optional v1 counter workflow after core accept/reject flow is stable.

## Epic 5: Payout and transaction visibility

### P1 — Farmer payout status tracking
- **TRD reference:** 5.3, 5.6
- **Backlog item:** Show payout milestones and current payment status for accepted contracts.
- **Acceptance notes:**
  - Farmers can see whether payout is pending, scheduled, or completed.
  - Status data stays consistent with contract and payment records.

### P1 — Farmer transaction history
- **TRD reference:** 5.6, 7
- **Backlog item:** Add a farmer-facing history view for submitted projects, accepted offers, contracts, and payouts.
- **Acceptance notes:**
  - Farmers can review past activity without needing operator support.
  - Data is scoped to the signed-in farmer only.

## Cross-cutting technical backlog

### P0 — Farmer portal authorization boundaries
- **TRD reference:** 4, 8, 10
- **Backlog item:** Enforce tenant-aware access rules so farmers can only view and update their own profiles, projects, documents, offers, and payouts.

### P0 — Audit trail for farmer actions
- **TRD reference:** 5.2, 5.6, 8, 10
- **Backlog item:** Record auditable events for project submission, document changes, resubmissions, and offer acceptance or rejection.

### P1 — Farmer notifications
- **TRD reference:** 3.1, 5.2
- **Backlog item:** Send email notifications for submission received, needs-info, approval, rejection, and offer creation events.
